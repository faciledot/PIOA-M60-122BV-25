2. Функциональность проекта.

Проект реализует in-memory базу данных для каталогизации MIDI-клавиатур.

В проекте реализованы возможности

&#x09;1) Добавления записей.

&#x09;У клавиатур есть параметры, такие как id, название компании-производителя, кол-во клавиш (от 1 до 88) , цена , наличие пэдов.

&#x09;2) Просмотра всех записей.

&#x09;3) Поиска с фильтрацией с любым сочетанием параметров.

&#x09;4) Обработка ошибок ввода (Некорректный ввод чисел, отрицательная цена, количество клавиш вне диапазона 1–88, неверное значение поля пэдов, дублирование ID, пустое название компании.)

&#x09;5) Сохранение записей при выборе файловой базы данных.

4. Разница между in-memory и файловой реализациями
В проекте реализованы два класса баз данных: `MidiKeyboardDB` (in-memory) и `FileMidiKeyboardDB` (файловая). Оба класса имеют одинаковый интерфейс — методы `create()` и `select()`, благодаря чему пользовательский интерфейс работает с ними единообразно.



\*\*In-memory реализация (MidiKeyboardDB)\*\* хранит данные в оперативной памяти в виде списка кортежей. При завершении программы все записи теряются. Подходит для тестирования и временного хранения.



\*\*Файловая реализация (FileMidiKeyboardDB)\*\* хранит данные в JSON-файле на диске. При создании записи данные автоматически сохраняются в файл, а при следующем запуске программы загружаются из него. Формат хранения — JSON-массив кортежей. Требует доступа к файловой системе. Работает медленнее из-за записи на диск при каждом добавлении, но обеспечивает постоянное хранение данных.



Таким образом, в in-memory реализации данные существуют только во время работы программы, а в файловой — сохраняются между запусками.
